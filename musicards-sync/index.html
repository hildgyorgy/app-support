MusiCards Sync

Support and privacy information

Help

MusiCards Sync keeps a music folder and a playback destination in sync, and publishes the library.json index used by MusiCards.

First setup

  1. Choose the source folder that contains your music library.
  2. Choose a local or remote destination. For a remote destination, enter its display name, host, user name, music-folder path and SSH port.
  3. Run Sync Preview to see which files and folders would change. Preview does not copy files or rebuild the library index.
  4. Run Sync to transfer the changes, generate the new library index and publish it to the destination.

Remote destinations

During first-time pairing, MusiCards Sync uses your SSH password to install its public key on the destination. The password is not saved. Later connections use the installed key, so switching between saved destinations does not require signing in again.

MusicBrainz-ready albums

The synchronization report shows how many album folders contain a MusicBrainz Release MBID. Tag albums with MusicBrainz Picard so MusiCards can match releases and tracks reliably.

Library index

A real sync removes the previous destination index before changing the music library. After the files are synchronized, MusiCards Sync publishes the newly generated index and verifies the result. This prevents an outdated index from describing a partly updated library.

Support

If pairing or synchronization fails, first confirm that the destination is reachable, SSH access is enabled, the destination path exists, and the user has permission to write there. The progress report contains the detailed rsync or SSH error.

Questions, suggestions and feedback are always welcome.

Privacy

MusiCards Sync does not require an account and contains no advertising or analytics.

  • Source and destination settings are stored locally on your Mac.
  • SSH passwords are used only during pairing and are never saved by the app.
  • Music files and the library index are transferred directly between your Mac and the selected destination. They are not sent through a developer-operated server.
  • Removing a saved remote location from the app does not delete music or SSH keys from the destination.
